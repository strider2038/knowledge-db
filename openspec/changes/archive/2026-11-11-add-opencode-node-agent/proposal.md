## Why

Нормализация узла и правка по инструкции запускают только `cursor-agent`. Нужна возможность выполнять те же джобы через OpenCode v2, в том числе с подпиской OpenCode Go, не убирая Cursor и не меняя HTTP-маршруты.

## What Changes

- Сервер выбирает агента узла по `KB_NODE_AGENT`: `cursor` (значение по умолчанию) или `opencode`.
- При `opencode` нормализация и agent-edit запускают OpenCode v2 (`opencode run`) в каталоге базы, с изолированным состоянием вне git-репозитория базы.
- Модель OpenCode задаётся `KB_NODE_AGENT_MODEL` (`provider/model`). Подписка OpenCode Go использует провайдер каталога `opencode-go` и ключ `OPENCODE_API_KEY`. Свой OpenAI-совместимый endpoint задаётся отдельно и не подменяет каталог Go.
- Неизвестный `KB_NODE_AGENT` и неполная конфигурация OpenCode останавливают старт `kb serve`. Отсутствие бинаря выбранного агента по-прежнему даёт 503 на старте джобы, без падения чтения базы.
- Официальный Docker-образ содержит и `cursor-agent`, и OpenCode v2. README описывает переключение и настройку OpenCode Go.
- Текст модалки «Редактировать с агентом» не называет конкретного поставщика.
- Маршруты, тела запросов и форма статуса/логов не меняются. **BREAKING:** нет. Строка ошибки 503 для режима `cursor` при отсутствии `cursor-agent` сохраняется.

## Capabilities

### New Capabilities

- Нет.

### Modified Capabilities

- `node-normalization`: нормализация идёт через настроенного агента узла (Cursor или OpenCode), а не только через Cursor Agent.
- `node-cursor-agent-edit`: правка по инструкции использует того же настроенного агента; имя возможности сохраняется.
- `rest-api`: старт нормализации и agent-edit требует доступности выбранного агента; код 503 сохраняется.
- `kb-unified-binary`: контейнерный runtime включает оба CLI.
- `node-action-panel`: пояснение в модалке инструкции не привязано к имени Cursor.

## Impact

- Backend: конфиг, общий раннер джоб узла, парсер логов OpenCode, wiring в bootstrap.
- API: те же `POST /api/nodes/normalize` и `POST /api/nodes/agent-edit`, те же GET статуса и логов. Меняется только диагностика недоступности выбранного агента.
- UI: одна фраза в модалке agent-edit. Новых экранов и полей нет.
- Данные: схема БД и формат узлов не меняются. Состояние OpenCode не пишется в репозиторий базы.
- Поставка: Dockerfile, `.env.example`, README.
- Потребители: существующие установки без `KB_NODE_AGENT` остаются на Cursor.
